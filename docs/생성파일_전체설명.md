# 생성 파일 전체 설명 (2026-08-23 작업분)

소상공인 6개 스냅샷 CSV + 생활인구 3개 CSV로부터 만든 파생 파일 9개를 정리한다. 파일 간 관계는 맨 아래 "전체 흐름" 참고.

---

## 1. `industries.csv` — 업종 마스터

**행 수**: 247행 (업종 소분류 1개당 1행)
**원천**: 6개 스냅샷 CSV 전부 동일한 업종분류 체계(소분류 247개)를 쓰는 걸 확인해서, 한 스냅샷(202312)에서만 추출.

| 컬럼 | 설명 |
|---|---|
| `상권업종대분류코드`/`custom_group` | 최상위 카테고리(10개: 음식/소매/과학·기술/수리·개인/교육/부동산/시설관리·임대/예술·스포츠/보건의료/숙박). `대분류명`을 그대로 `custom_group`으로 채택 |
| `상권업종중분류코드`/`상권업종중분류명` | 중분류(75개) |
| `상권업종소분류코드`/`상권업종소분류명` | 소분류(247개) — "동일 업종" 판정 기준이 되는 가장 세부 단위 |

**중요 발견**: 원래 "구버전 837개 vs 신버전 247개 매핑이 필요할 것"이라 가정했는데, 실제 6개 CSV 전부 신버전(247개) 하나로 통일돼 있었다. 복잡한 텍스트 기반 매핑 없이 이 테이블 하나로 끝났다.

## 2. `store_panel_master.csv` — 메인 통합 패널 (가장 중요한 파일)

**행 수**: 3,145,970행 (6개 스냅샷 × 매장, long format)
**용도**: 이후 만든 거의 모든 파일이 이 파일에서 파생됨.

| 컬럼 | 설명 |
|---|---|
| `snapshot_date` | 202312~202606 중 하나 |
| `상가업소번호` | 매장 식별자. 스냅샷 내에서 100% 유일함을 검증 완료 |
| `상호명` | 상호명 원본 텍스트 |
| `상권업종대/중/소분류코드·명` | 업종 분류 |
| `시군구명`, `행정동코드`, `행정동명` | 위치(행정구역) |
| `경도`, `위도` | 좌표 |
| `same_industry_count_300m` | 반경 300m 내 동일 업종(소분류 기준) 매장 수. BallTree(haversine)로 계산 |
| `is_closed_next` | **다음** 스냅샷에서 이 매장이 사라졌는지 (폐업 라벨의 원재료) |
| `transitioned_next` | 다음 스냅샷으로 갈 때 업종(소분류)이 바뀌었는지 |
| `label_available` | 202606(마지막 스냅샷)만 False — 다음 시점이 없어서 라벨을 매길 수 없음(서빙 전용) |
| `trend_keyword_match` | 상호명에 트렌드 키워드(탕후루/버터/마라탕/흑당/요거트/무인/셀프/인형뽑기/인생네컷/방탈출/스크린골프/만화카페/애견카페/스터디카페 중 하나) 포함 여부 |

**알아둘 점**: `is_closed_next`가 True인 매장이 나중 스냅샷에 다시 나타나는 경우(일시적 데이터 공백)가 있다 — 이건 `stores_master.csv`에서 별도로 처리했다(아래 참고).

## 3. `stores_master.csv` — 매장별 요약

**행 수**: 778,895행 (유니크 매장 1개당 1행)
**원천**: `store_panel_master.csv`를 `store_id`로 집계.

| 컬럼 | 설명 |
|---|---|
| `store_id` | |
| `first_seen_snapshot` | 처음 관측된 스냅샷 |
| `last_seen_snapshot` | 마지막으로 관측된 스냅샷 |
| `current_industry_code` | 마지막 관측 시점의 업종 |
| `dong_code` | 마지막 관측 시점의 행정동 |
| `n_snapshots_observed` | 총 몇 번 관측됐는지 |
| `is_closed` | **최종** 폐업 여부. `last_seen_snapshot != 202606`이면 True (마지막 스냅샷까지 살아있지 않으면 폐업으로 판정) |
| `had_temporary_gap` | 관측 구간 중간에 한 번 이상 빠졌다가 다시 나타난 적이 있는지 (14,074건, 약 1.8%) |

**버그 수정 이력**: 처음엔 "한 번이라도 `is_closed_next=True`로 찍힌 적이 있으면 폐업"으로 정의했었는데, 이러면 중간에 잠깐 빠졌다가 재등장한 매장까지 폐업으로 오분류됐다. `last_seen_snapshot` 기준으로 재정의해서 수정. 전체 매장의 28.9%(224,803개)가 최종 폐업으로 판정됨 — 이 수치가 정확히 202606 스냅샷 행 수(554,092)와 상호보완적으로 맞아떨어지는 것도 확인함(778,895 - 224,803 = 554,092).

## 4. `industry_transitions.csv` — 업종전환 이력

**행 수**: 21,767행
**원천**: 인접 스냅샷 쌍에서 같은 `store_id`가 존재하는데 업종 코드만 바뀐 경우.

| 컬럼 | 설명 |
|---|---|
| `transition_id` | |
| `store_id` | |
| `from_snapshot`, `to_snapshot` | 전환이 관측된 스냅샷 구간 |
| `from_industry_code`, `to_industry_code` | 전환 전/후 업종 |

**알아둘 점**: 전환 건수가 스냅샷 구간마다 들쭉날쭉하다 — 202406→202412 구간에 21,194건(전체의 97%)이 몰려있고, 나머지 구간은 0건이거나 극소수(202512→202606에 573건)다. 소상공인시장진흥공단이 업종분류를 특정 시점에만 일괄 재정비하는 것으로 보인다. 결과서에 이 패턴을 있는 그대로 언급하는 게 좋다.

---

## 5. `industry_survival_stats.csv` — 업종전환 생존율

**행 수**: 3,529행 (from-to 조합 1개당 1행)
**원천**: `industry_transitions.csv`를 (from, to) 조합별로 집계, 전환 직후 다음 스냅샷까지 생존했는지로 생존율 계산.

| 컬럼 | 설명 |
|---|---|
| `from_industry_code`, `to_industry_code` | 전환 조합 |
| `sample_size` | 이 조합의 관측 건수 |
| `survival_rate` | 전환 후 생존 비율 |

**한계**: "생존"의 기준이 "전환 직후 다음 스냅샷까지만" 살아있었는지라 관측 기간이 짧다(단기 생존 프록시). 표본이 적은 조합(예: 1~2건)은 추천에 쓰기엔 신뢰도가 낮으니 `sample_size`로 걸러써야 한다.

## 6. `trend_keywords.csv` — 키워드 트렌드

**행 수**: 14행 (키워드 1개당 1행)
**원천**: `store_panel_master.csv`의 상호명을 스냅샷별로 키워드 매칭 집계.

| 컬럼 | 설명 |
|---|---|
| `keyword` | 탕후루/버터/마라탕/흑당/요거트/무인/셀프/인형뽑기/인생네컷/방탈출/스크린골프/만화카페/애견카페/스터디카페 |
| `202312`~`202606` | 스냅샷별 매장 수 |
| `growth_rate` | (202606 - 202312) / 202312 |

**결과**: 인형뽑기 +184%, 요거트 +80%, 무인매장 +57%가 상승세 상위. 탕후루는 -89.6%로 이미 하락 중 — 더미 데이터가 아니라 실데이터라서 나올 수 있었던 결과.

## 7. `population_features.csv` — 생활인구 (행정동 단위)

**행 수**: 424행 (행정동 1개당 1행)
**원천**: 생활인구 3개 CSV(내국인/외국인장기/외국인단기)를 행정동×날짜×시간대로 평균.

| 컬럼 | 설명 |
|---|---|
| `dong_code`, `dong_name`, `gu_name` | 행정동 정보 |
| `korean_pop`, `foreign_long_pop`, `foreign_short_pop` | 각각의 평균 생활인구 |
| `total_pop_avg` | 셋의 합 |
| `foreign_short_ratio` | 단기외국인 비율 |
| `tourist_zone_candidate` | 위 비율 상위 10%면 True |

**중요 발견**: 원래 "최신 시점 1개 스냅샷"이라 가정했는데, 실제로는 **2026년 7월 한 달치(31일×24시간대)** 데이터였다. 하루치가 아니라 한 달 평균이라 더 안정적인 값이 됨. 또한 **파일 구조 버그**가 있었다 — 헤더보다 데이터 컬럼이 1개 더 많아서(끝에 빈 컬럼) 기본 설정으로 읽으면 날짜/시간대/행정동코드가 한 칸씩 밀려 잘못 매칭됐다. `index_col=False` 옵션으로 수정.
**검증**: 단기외국인 비율 1위가 명동(중구)으로 나와서 관광특구 데이터로서 타당성 확인됨.
**주의**: 소상공인 데이터의 행정동코드와 매칭 안 되는 행정동이 9개 있음(424개 중).

## 8. `modeling_dataset.csv` — 모델 학습용 최종 데이터

**행 수**: 2,591,877행
**원천**: `store_panel_master.csv`(label_available=True인 행만) + `population_features.csv`를 `dong_code`로 조인, GroupKFold(store_id 해시 기반, K=5) fold 배정.

컬럼 구성은 바로 위 답변에서 표로 정리했던 21개 컬럼과 동일 — 식별정보(snapshot_date/store_id/fold), 업종 피처(industry_dae/jung/code, industry_group), 위치 피처(gu_name/dong_code/lng/lat), 공간밀도(same_industry_count_300m), 생활인구 피처(korean_pop 등), 기타(trend_keyword_match/transitioned_next), 타겟(is_closed_next).

**결측치**: 생활인구 조인 실패한 약 3.7만 행(1.4%)에 population 관련 컬럼이 비어있음.
**클래스 비율**: `is_closed_next` 양성(폐업) 비율 약 9.2%.

## 9. `lightgbm_baseline.txt` — 베이스라인 모델 (검증용)

`modeling_dataset.csv`가 실제로 학습에 쓰일 수 있는지 검증하기 위해 fold 4를 테스트셋으로 잡고 LightGBM으로 빠르게 학습시킨 결과물(모델 파일 자체).

**성능**: Accuracy 0.606 / Precision 0.137 / Recall 0.620 / F1 0.225 / ROC-AUC 0.659
**Feature importance 상위**: dong_code > industry_code > same_industry_count_300m > lat/lng
**주의**: 이건 하이퍼파라미터 튜닝 없이 파이프라인 검증 목적으로만 돌린 결과라, 실제 제출용 모델은 아니다. train/test 간 store_id 중복 0건은 확인 완료(데이터 누수 없음).

## 전체 흐름 요약

```
[소상공인 원본 6개 CSV] ──┬─→ industries.csv (업종 마스터)
                          ├─→ store_panel_master.csv (메인 패널)
                          │      ├─→ stores_master.csv (매장 요약)
                          │      ├─→ industry_transitions.csv → industry_survival_stats.csv
                          │      └─→ trend_keywords.csv
                          │
[생활인구 원본 3개 CSV] ──┴─→ population_features.csv
                                    │
                     store_panel_master.csv + population_features.csv
                                    │  (dong_code로 조인, label_available=True만)
                                    ▼
                          modeling_dataset.csv
                                    │
                                    ▼
                          lightgbm_baseline.txt (검증용 1차 모델)
```
