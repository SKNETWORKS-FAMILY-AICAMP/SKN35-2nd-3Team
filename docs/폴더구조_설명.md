# 프로젝트 폴더 구조 설명

이 문서는 `seoul-closure-prediction` 폴더 안에 있는 각 폴더/파일이 정확히 무엇을 위한 것인지 설명합니다. 비유 없이 실제 역할 그대로 적었습니다.

---

## 1. data — 데이터 저장

프로젝트에서 쓰는 모든 데이터 파일이 단계별로 나뉘어 저장되는 곳입니다.

### data/raw
- 아무 가공도 하지 않은 원본 CSV 파일
- `data/raw/sbiz/` : 소상공인시장진흥공단 상가정보 CSV, 202312~202606까지 6개월 단위 6개 스냅샷
- `data/raw/population/` : 서울 생활인구 CSV (내국인 / 외국인 장기체류 / 외국인 단기체류), 최신 시점 1개만 사용
- 이 폴더 안의 파일은 절대 직접 수정하지 않습니다. 수정이 필요하면 새 파일을 만들어 `data/processed`에 저장합니다.

### data/processed
- raw 파일의 인코딩 문제(BOM 등)나 형식 오류를 고친 결과물
- 아직 분석용으로 완전히 정리된 상태는 아니고, "읽을 수 있게 만든" 단계

### data/labeled
- 상가업소번호를 기준으로 스냅샷 간 비교를 해서 "폐업했는지 아닌지" 라벨을 붙인 데이터셋
- 모델 학습에 쓸 정답(타겟)이 포함된 상태

### data/features
- 모델에 바로 입력할 수 있는 최종 피처 테이블
- 공간 밀도, 업종 그룹, 생활인구 등 여러 곳에서 만든 피처들을 다 합쳐놓은 상태

---

## 2. db — 데이터베이스 설계 및 적재

- `db/schema.sql` : 테이블 구조를 정의하는 DDL(Data Definition Language) 코드
- `db/erd.png`, `db/erd.drawio` : ERD(테이블 간 관계를 그림으로 정리한 것)
- `db/etl/` : CSV 파일을 실제 데이터베이스에 넣는 스크립트들. 스냅샷별 적재, 생활인구 적재, 피처 뷰 생성 등이 여기 들어갑니다.

---

## 3. features — 피처 계산 로직

원본 데이터를 모델이 이해할 수 있는 숫자(피처)로 바꾸는 코드가 들어갑니다. 폴더별로 계산하는 내용이 다릅니다.

- `features/spatial/` : 위치 기반 계산. 예를 들어 반경 300m 안에 같은 업종 가게가 몇 개 있는지 세는 코드
- `features/industry_grouping/` : 업종 분류 코드가 바뀐 문제(837개 → 247개)를 해결하기 위해, 업종명 텍스트를 기준으로 새로운 그룹(8~12개)을 만드는 코드
- `features/trend_keywords/` : 상호명에 특정 키워드(탕후루, 버터떡 등)가 들어간 가게 수를 6개 스냅샷에 걸쳐 세서 증가율을 계산하는 코드
- `features/survival_transition/` : 한 가게가 업종을 바꾼 이력을 추적해서, 어떤 업종으로 바꿨을 때 생존율이 높았는지 계산하는 코드

---

## 4. models — 모델 학습

- `models/ml/` : 머신러닝 모델(로지스틱 회귀, 랜덤포레스트, LightGBM 등) 학습 코드. `saved/` 폴더에 학습이 끝난 모델 파일을 저장합니다.
- `models/dl/` : 딥러닝 모델(MLP) 학습 코드. 마찬가지로 `saved/`에 결과물을 저장합니다.
- `models/shap/` : SHAP을 이용해서 모델이 왜 그렇게 예측했는지 설명하는 코드. 사용자에게 "왜 위험도가 높다고 나왔는지" 보여주는 데 씁니다.

---

## 5. app — 실제로 실행되는 앱 (Streamlit)

사용자가 직접 쓰는 화면입니다. Streamlit이라는 도구로 만들고, 사용자 그룹(예비창업자/기존점주/관리자)별로 파일을 나눴습니다.

- `app/app.py` : 앱을 실행하면 제일 먼저 보이는 화면. 사용자가 어떤 유형인지 선택하고 로그인하는 부분
- `app/requirements.txt` : 앱을 실행하는 데 필요한 라이브러리 목록 (streamlit, plotly 등)
- `app/build_features_and_model.py` : 앱을 처음 실행하기 전에 한 번 돌려서, 학습된 모델과 피처 테이블을 앱이 바로 쓸 수 있는 형태로 준비해두는 스크립트
- `app/pages/` : 실제 화면 파일들이 들어있는 폴더. Streamlit은 이 폴더 안의 파일을 자동으로 인식해서 왼쪽 메뉴에 순서대로 보여줍니다.
  - `1_founder_score.py` : 예비창업자용 - 위치+업종 위험도/추천도 점수 화면
  - `2_owner_healthcheck.py` : 기존점주용 - 내 가게 위험도 점수 + 이유 설명 화면
  - `3_owner_industry_switch.py` : 기존점주용 - 업종 변경 추천 화면
  - `4_admin_login.py` : 관리자 로그인 화면
  - `5_admin_dashboard.py` : 관리자용 - 위험한 상권 모니터링 화면
  - `6_admin_trend.py` : 관리자용 - 요즘 뜨는 업종 화면
- `app/shared/` : 여러 화면에서 공통으로 쓰는 코드
  - `auth.py` : 로그인 처리
  - `db.py` : 데이터베이스에서 데이터 가져오는 코드
  - `components.py` : 위험도 배지 같은 반복해서 쓰는 화면 부품
- `app/founder/`, `app/owner/`, `app/admin/` : 각 화면에서 쓰는 세부 로직 코드 (화면 파일 자체가 아니라, 그 화면이 불러다 쓰는 함수/로직)

**실행 순서**
```
pip install -r requirements.txt          # 데이터/모델 작업에 필요한 라이브러리 설치
pip install -r app/requirements.txt      # 앱 실행에 필요한 라이브러리 설치
python app/build_features_and_model.py   # 모델과 피처를 앱이 쓸 수 있게 준비 (최초 1회만)
streamlit run app/app.py                 # 앱 실행
```

## 7. notebooks — 실험 공간

정식 코드로 옮기기 전에 데이터를 살펴보거나(EDA), 피처가 제대로 계산되는지 테스트하거나, 모델을 이것저것 시도해보는 용도의 주피터 노트북을 두는 곳입니다. 여기 있는 코드는 완성된 코드가 아니어도 괜찮습니다.

---

## 전체 작업 흐름 정리

1. `data/raw`에 원본 CSV를 넣는다
2. `data/processed`로 정리한다
3. `data/labeled`로 폐업 라벨을 붙인다
4. `features/` 안의 코드들로 피처를 계산해서 `data/features`에 최종 표를 만든다
5. `models/`에서 그 표로 모델을 학습시키고 `saved/`에 저장한다
6. `app/`에서 그 모델을 불러와 실제 화면으로 보여준다

---

## 아직 정해지지 않은 것
- `db/schema.sql`(실제 DDL) — ERD는 나왔지만 아직 문서화 전입니다. DB는 TiDB(MySQL 호환)로 확정됨.
- TiDB에 실제로 적재하는 스크립트
- `app/`의 각 화면 로직 (지금은 스텁 파일만 있음)
- Random Forest, MLP와의 성능 비교
